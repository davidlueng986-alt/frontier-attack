## Why 0 mismatches carries no information

LMFDB is curated. A curve with `rank != analytic_rank` would be one of the most
famous entries in the table, not a routine record returned by a `rank=4` query.
The scan asked a database that is *defined* to be consistent whether it is
consistent. The answer was always going to be no mismatches.

What the run does establish: the gatekeeper accepts 50/50 legitimate claims and
raised no false alarms. For a gate, that is the property that matters — a gate
that rejects everything is as useless as one that accepts everything.

What it does not establish: anything about BSD.

## This is the substitution phenomenon, in miniature

This agent produced a correct, reproducible, verified artifact that is **not on
the core**. It is the exact behaviour described in `docs/ORCHESTRATION.md` §1-2:

- The core is: compute `rank` and `ord_{s=1} L` for a curve where they might
  differ.
- The adjacent closable problem is: scan a curated database for a difference
  that curation forbids.
- The adjacent problem closed. The core did not move.
- Nothing in the pipeline flagged this, because the artifact passed the checker.

**A checker verifies truth, not relevance.** That is why admissibility has to be
a separate gate: the artifact must be an object the *terminal* checker consumes.
`bsd.check_claim` is not terminal — it is a sanity filter. The terminal checker
is `rank != analytic_rank` with two independent backends, and nothing in this
run produced an input to it.

## The admissible next action

Not more records. A curve outside LMFDB's curated set, with:

1. `rank` from an actual `2-descent` / `mwrank` run (not a database field), and
2. `ord_{s=1} L` from a numerical derivative with explicit error bounds, and
3. a stated conductor range where the computation is feasible.

That is a backend task, not an agent task. Until the backend exists, the correct
output of this branch is `NO_ADMISSIBLE_ACTION`, and the next hire is a
Cartographer who can size the conductor range.
